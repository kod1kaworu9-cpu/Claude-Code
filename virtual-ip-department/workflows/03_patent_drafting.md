# ワークフロー：特許明細書・請求項作成（Patent Drafting）

## 概要
発明提案書に基づき、特許出願用の明細書及び請求項を作成するプロセス。

## 起動コマンド
`/ip-draft`

## 担当メンバー
- **主担当**: 佐藤 理恵（明細書・請求項作成）
- **レビュー**: 田中 健太（先行技術観点） + 山本 彩花（RAPIDレビュー）
- **最終承認**: 高橋 誠一

---

## 実行フロー

```
┌──────────────────────────────────────────────────┐
│ Step 1: 事前準備【佐藤】                             │
│  ├── 発明提案書の精読                                │
│  ├── 先行技術調査結果の確認（あれば）                 │
│  ├── 出願戦略の確認（高橋と協議）                     │
│  │   ├── 単独出願 or PCT出願                        │
│  │   ├── 請求項の数・カテゴリー                      │
│  │   └── 明細書のボリューム                          │
│  └── 図面作成の指示準備                              │
├──────────────────────────────────────────────────┤
│ Step 2: 請求項設計【佐藤】                           │
│  ├── 独立請求項の起案                                │
│  │   ├── 構成要件の必要十分性の検討                   │
│  │   ├── 最適な表現方法の選択                        │
│  │   │   ├── 機能的表現 vs 構造的表現               │
│  │   │   ├── オープンクレーム vs クローズドクレーム   │
│  │   │   └── 手段＋機能（Means-plus-function）の検討 │
│  │   └── 複数カテゴリーの検討                        │
│  │       ├── 装置クレーム                            │
│  │       ├── 方法クレーム                            │
│  │       ├── プログラムクレーム                      │
│  │       └── 記録媒体クレーム                        │
│  ├── 従属請求項ツリーの設計                          │
│  │   ├── フォールバックポジションの確保               │
│  │   ├── 実施形態の特徴との対応                      │
│  │   └── 分割出願の種（シード）の埋め込み             │
│  └── 請求項ドラフト完成                              │
├──────────────────────────────────────────────────┤
│ Step 3: 請求項レビュー【田中＋山本】                   │
│  ├── 田中：先行技術との差別化確認                     │
│  │   ├── 新規性の確認                                │
│  │   ├── 進歩性の論拠の確認                          │
│  │   └── 審査で問題になりそうな点の指摘               │
│  ├── 山本：RAPIDレビュー                             │
│  │   ├── 権利範囲の適切性                            │
│  │   ├── 回避容易性の評価                            │
│  │   └── 無効リスクの評価                            │
│  └── 指摘事項に基づく請求項修正【佐藤】               │
├──────────────────────────────────────────────────┤
│ Step 4: 明細書本文執筆【佐藤】                        │
│  ├── 発明の名称                                      │
│  ├── 技術分野                                        │
│  ├── 背景技術                                        │
│  ├── 発明が解決しようとする課題                       │
│  ├── 課題を解決するための手段                         │
│  ├── 発明の効果                                      │
│  ├── 図面の簡単な説明                                │
│  ├── 発明を実施するための形態                         │
│  │   ├── 第1の実施形態（基本）                       │
│  │   ├── 第2の実施形態（変形例）                     │
│  │   ├── 第3の実施形態（応用例）                     │
│  │   └── その他の変形例                              │
│  ├── 要約書                                          │
│  └── 図面                                            │
├──────────────────────────────────────────────────┤
│ Step 5: 全体クロスレビュー【全員】                     │
│  ├── 佐藤：セルフレビュー（記載要件の確認）            │
│  ├── 田中：審査観点レビュー（拒絶理由の想定）          │
│  ├── 山本：品質管理レビュー（RAPID＋整合性）          │
│  └── 高橋：戦略的レビュー（事業保護の観点）            │
├──────────────────────────────────────────────────┤
│ Step 6: 最終化【佐藤→高橋承認】                      │
│  ├── 全レビュー指摘事項への対応                       │
│  ├── 最終整合性チェック                              │
│  └── 高橋による最終承認                              │
└──────────────────────────────────────────────────┘
```

## 記載要件チェックリスト

### 実施可能要件（特許法36条4項1号）
- [ ] 当業者が明細書の記載に基づいて発明を実施できるか
- [ ] 技術用語は正確に使用されているか
- [ ] 実施例は十分に具体的か
- [ ] 数値範囲がある場合、臨界的意義は説明されているか

### サポート要件（特許法36条6項1号）
- [ ] 各請求項の構成要件は明細書に裏付けがあるか
- [ ] 上位概念の請求項は、下位概念の実施例で十分にサポートされているか
- [ ] 機能的クレームの場合、その機能を実現する具体的手段が開示されているか

### 明確性要件（特許法36条6項2号）
- [ ] 各請求項の記載は第三者が権利範囲を理解できる程度に明確か
- [ ] 「約」「概ね」「実質的に」等の不明確な表現はないか（あればその必要性）
- [ ] 請求項の各構成要件の関係は明確か

### 単一性要件（特許法37条）
- [ ] 複数の請求項は単一の発明概念に基づいているか
- [ ] 異なるカテゴリーの請求項の関係は適切か

### 整合性チェック
- [ ] 請求項の用語と明細書の用語は一致しているか
- [ ] 図面番号は明細書の記載と一致しているか
- [ ] 段落番号は連続しているか
- [ ] 符号の説明は網羅的か
